Journeys

A journey connects a business requirement and KPI to the stages of a customer path, each measured by a component. Build one in a form, picking components you have already synced and curated, or import many at once from a CSV below.

Shared library

Requirements and KPIs that several journeys use. Each is stored once, so changing it here changes every journey that uses it. Deleting a journey never deletes its library entries; an entry no journey uses stays here with a count of 0. The library belongs to your own data; the demo data is read-only and has none.

Settings

Every component's component_xdm_path column (e.g. commerce.checkouts.value) gets appended to this prefix to build its martech:refs URI when you click Generate turtle. Set this to your org's real AEP sandbox once. It's just a prefix string, not validated against Adobe's actual URL scheme. Changing it only affects journeys generated after the change; existing files keep whatever refs they already have.

Import from CSV

Or paste CSV content:

If a component_key already exists in another data file (e.g. synced from CJA and curated on the Components page), the journey references that component and keeps its curated context; the component_* columns in your CSV are ignored for it. Only new keys are defined by the journey.
