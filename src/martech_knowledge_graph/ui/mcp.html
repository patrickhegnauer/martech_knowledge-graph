Built — run it from a terminal. There's no one-click "start" button on this page yet (that's a deliberate next step, not a gap); until then, the CLI is the real, working way to run it.

Run it

martech-knowledge-graph mcp

Reads the same --data-dir and demo/org mode martech-knowledge-graph serve uses (shares its .mkg-mode file) — switching workspaces in the browser is reflected on the MCP server's very next tool call, no restart needed. By default it prints and serves at http://127.0.0.1:8931/mcp — point any MCP-compatible client (Claude, an agent framework, etc.) at that URL.

Two transports — pick based on your client

--transport http (the default, shown above) runs a persistent server at a URL — use this for anything that connects over the network: claude.ai's Custom Connectors, a coworker on another machine, an agent framework. --transport stdio is for a client that spawns the process itself from a local config file, with no URL involved — this is how Claude Desktop's "Local MCP Servers" config works.

For Claude Desktop, add this to claude_desktop_config.json (Settings → Developer → Edit Config), using the full path to the installed console script so it resolves regardless of Claude Desktop's own PATH:

{
  "mcpServers": {
    "martech-knowledge-graph": {
      "command": "C:\\path\\to\\python\\Scripts\\martech-knowledge-graph.exe",
      "args": ["mcp", "--transport", "stdio", "--data-dir", "C:\\path\\to\\your\\martech-knowledge-graph-data"]
    }
  }
}

Find your own martech-knowledge-graph.exe path by running where martech-knowledge-graph (Windows) or which martech-knowledge-graph (macOS/Linux) in the same terminal you installed it from. Restart Claude Desktop after editing the config. No URL, no --host/--port — Claude Desktop spawns and owns the process directly.

Publish to Prefect Horizon (hosted URL)

martech-knowledge-graph export-mcp --out ./my-mcp

Writes a self-contained folder (entrypoint, a snapshot of your data, requirements, step-by-step README). Push it to your own private GitHub repo and deploy it on Horizon with entrypoint server.py:mcp to get a https://<name>.fastmcp.app/mcp URL. Re-run and push to refresh the snapshot.

Tool set

Single-doorway principle: one query interface, not multiple competing tools.

ToolPurpose
run_sparql Runs a read-only SPARQL query (SELECT / ASK / CONSTRUCT / DESCRIBE) against the currently active workspace's graph. Write forms (INSERT/DELETE) aren't filtered out — they simply fail to parse against rdflib's read-only query grammar, so there's no separate check that could have a gap in it.
get_ontology_schema Returns every class and property in the ontology — name, comment, and (for properties) domain/range — extracted live from martech-ontology.ttl, so it can't drift out of sync with the real schema. Meant to be called before run_sparql by a caller that doesn't already know the graph's shape.

Security posture

The local server has no authentication — it binds to 127.0.0.1 only by default, matching every other part of this tool's local-first trust model (same as martech-knowledge-graph serve). Reachable only from the machine it runs on unless you deliberately pass --host to change that. A server deployed on Prefect Horizon is public-facing but protected by Horizon's OAuth (it cannot be switched off on the free tier), and its data is a snapshot in your own private repository.

Generate a skill for your org

A skill file tells an AI agent how to use this MCP connection well — what the graph means, example queries, what to watch out for. The SKILL.md in this repo documents the bundled demo workspace; the button below drafts one grounded in your own data instead: it pulls the live ontology schema and runs the example queries against your graph right now, so the draft shows real row counts, not guesses. It's a starting point — finish the wording (and the "Things to get right" section) by hand or hand it to your own LLM; there's no AI built into this app to do that part for you.
